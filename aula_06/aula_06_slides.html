Parte 1

Governança de Dados — conceito, papéis e maturidade

MACKENZIE

🏛️ O que É (e o que Não É) Governança de Dados

Governança NÃO é:

  • Apenas segurança de TI (firewall, criptografia)
  • Apenas qualidade de dados
  • Apenas compliance regulatório
  • Responsabilidade exclusiva da área de TI
  • Um projeto com início, meio e fim

Governança É:

  • Conjunto de políticas, processos, papéis e responsabilidades
  • Quem decide o que os dados significam (semântica)
  • Quem autoriza o acesso a quais dados e por quê
  • Quem é responsável quando um dado está errado
  • Como os dados evoluem e são curados ao longo do tempo
Governança de dados sem o envolvimento do negócio é burocracia técnica. Governança de dados sem execução técnica é intenção sem efeito. Precisa dos dois.
MACKENZIE

👥 Os 5 Papéis de Governança

Chief Data Officer (CDO)

Define a estratégia de dados da organização, garante o ROI dos investimentos em dados e constrói a cultura data-driven. Representa os dados no C-Suite — sem CDO, dados são prioridade de ninguém.

Data Owner (Diretor de área)

Responsável pelo dado do seu domínio: define regras de negócio, autoriza acessos, aprova critérios de qualidade. É o "dono" do dado — não da tecnologia que o armazena.

Data Steward (Analista sênior da área)

Cuida do dado no dia a dia: documenta no catálogo, monitora qualidade, responde dúvidas dos consumidores. É o braço operacional do Data Owner.

Data Custodian (TI / Engenharia de Dados)

Armazena, integra e implementa os controles definidos pelo negócio. Executa as políticas, não as define.

DPO — Data Protection Officer

Garante conformidade com a LGPD. Ponto de contato com a ANPD e com os titulares de dados. Obrigatório por lei para a maioria das organizações.

MACKENZIE

👥 Como os Papéis Interagem na Prática

Um pedido de acesso a dados percorre todos os papéis. Entender o fluxo evita gargalos e decisões erradas.

SituaçãoQuem ageO que faz
Analista de marketing quer acesso aos dados de saúde dos clientesDPO + Data OwnerDPO avalia se há base legal; Data Owner decide se o acesso é necessário para a finalidade
Campo "receita líquida" tem definições diferentes em 3 sistemasData Owner + Data StewardData Owner define a versão oficial (golden record); Steward documenta e comunica
Sistema legado vai ser desativadoData Custodian + Data StewardCustodian mapeia dependências técnicas; Steward identifica quem usa os dados
Relatório executivo mostra número divergenteData Steward + Data CustodianSteward investiga a causa; Custodian rastreia pelo lineage
Novo parceiro quer receber dados dos clientesDPO + Data Owner + CDODPO avalia LGPD; Owner decide; CDO avalia risco estratégico
MACKENZIE

🔑 Controle de Acesso — Princípio do Menor Privilégio

O princípio do menor privilégio (least privilege) define que cada pessoa deve ter acesso apenas aos dados estritamente necessários para sua função — nem mais, nem menos.

Modelos de controle de acesso

  • Need-to-know: acesso concedido apenas a quem demonstra necessidade específica
  • Role-Based (RBAC): acesso definido pelo cargo/função (ex.: "analista financeiro" acessa dados financeiros)
  • Attribute-Based (ABAC): acesso definido por atributos combinados (cargo + área + projeto + sensibilidade do dado)

O que acontece sem controle

  • Funcionários veem dados que não deveriam — risco de vazamento interno
  • Terceiros e prestadores com acesso amplo são os vetores mais comuns de incidentes
  • Sem log de acesso, é impossível investigar o que foi visto depois de um incidente
O caso Claro (2023): o incidente foi possível porque prestadores tinham acesso a volumes muito maiores do que precisavam — violação direta do menor privilégio.
MACKENZIE

📊 Modelo de Maturidade em Governança de Dados

0
Inexistente — Sem políticas; cada área faz o que quer; ninguém é responsável por nenhum dado
1
Reativo — Políticas surgem após incidentes; gestão apagando incêndio; papéis informais
2
Definido — Políticas documentadas; papéis formalizados; execução ainda inconsistente
3
Gerenciado — Políticas aplicadas com monitoramento; métricas de conformidade; Data Owners ativos
4
Otimizado — Governança automatizada; medida continuamente; cultura data-driven consolidada
Diagnóstico rápido: Se a pergunta "quem é o responsável por esse dado?" gera silêncio na reunião, a organização está no Nível 0 ou 1. A maioria das empresas brasileiras está entre 1 e 2.

LGPD — o que todo gestor de dados precisa saber

MACKENZIE

🔒 Tipos de Dados — Do Pessoal ao Sensível

TipoDefiniçãoExemplosNível de proteção
Dado pessoalIdentifica ou pode identificar uma pessoa naturalNome, CPF, e-mail, endereço, IP, número de telefonePadrão — bases legais gerais se aplicam
Dado sensívelPode gerar discriminação ou é de natureza íntimaSaúde, genética, biometria, religião, orientação sexual, raça, filiação políticaElevado — bases legais específicas + controles adicionais
Dado de criança/adolescenteDado pessoal de menores de 18 anosQualquer dado de menorMáximo — consentimento dos pais obrigatório

⚖️ Bases Legais — Por que Posso Tratar Esse Dado?

Todo tratamento de dados pessoais precisa de uma base legal. Sem ela, o tratamento é ilegal — independentemente da utilidade do dado.

Base legalQuando usarLimitaçõesExemplo
ConsentimentoUsuário autorizou expressamente, de forma específica e informadaPode ser revogado a qualquer momento — não é a base mais robustaNewsletter opt-in, uso de cookies de rastreamento
ContratoNecessário para executar o contrato com o próprio titularSó vale para o que é estritamente necessário para o contratoDados de entrega para uma compra online
Obrigação legalUma lei ou regulação exige o tratamentoExige norma legal expressa; não vale "é uma boa prática"Nota fiscal, eSocial, SPED
Interesse legítimoInteresse razoável do controlador, sem prejudicar o titularRequer teste de proporcionalidade — não vale para dado sensívelPrevenção a fraudes, segurança de rede
Tutela da saúdePor profissional de saúde para proteção da vidaRestrita a serviços de saúdeHistórico clínico para diagnóstico
MACKENZIE

👤 Direitos do Titular — O que Qualquer Cidadão Pode Exigir

A LGPD garante ao titular (a pessoa cujos dados são tratados) um conjunto de direitos que a organização tem obrigação de atender.

DireitoO que significaPrazo de resposta
Confirmação e acessoSaber se a empresa trata seus dados e quais são elesImediato ou em até 15 dias
CorreçãoCorrigir dados incompletos, inexatos ou desatualizadosEm prazo razoável
Anonimização ou exclusãoEliminar dados desnecessários ou tratados em desconformidadeEm prazo razoável
PortabilidadeReceber seus dados em formato estruturado para transferir a outro fornecedorMediante regulamentação da ANPD
Revogação do consentimentoRetirar o consentimento dado anteriormente, a qualquer momentoImediato
OposiçãoSe opor a tratamento baseado em interesse legítimo que cause danoEm prazo razoável
Implicação prática: a organização precisa de processos e sistemas que permitam localizar, exportar e excluir todos os dados de um titular específico. Sem isso, os direitos são letra morta.
MACKENZIE

📋 O que Fazer na Prática — 7 Obrigações

  1. Mapeamento: saber quais dados pessoais você trata, onde estão, por quê e com base em qual base legal
  2. Minimização: coletar apenas o necessário para a finalidade declarada — não "coletar tudo e ver o que serve depois"
  3. Finalidade: usar os dados só para o propósito informado — não reutilizar para fins diferentes sem nova base legal
  4. Segurança: medidas técnicas (criptografia, controle de acesso) e organizacionais (treinamento, política) para proteger os dados
  1. Transparência: informar os titulares em linguagem clara sobre como seus dados são tratados (Política de Privacidade)
  2. Direitos do titular: ter processo definido para responder solicitações em até 15 dias
  3. Incidentes: notificar a ANPD e os titulares afetados em caso de vazamento "em prazo razoável" — na prática, o mais rápido possível
Penalidade máxima: 2% do faturamento do grupo econômico no Brasil, limitado a R$ 50 milhões por infração.
MACKENZIE

Parte 3

Data Mesh — governança distribuída para organizações que escalam

MACKENZIE

🕸️ O Problema que o Data Mesh Resolve

Em organizações grandes, a governança centralizada cria um gargalo clássico:

Sintomas do gargalo central

  • O time central de dados tem fila de semanas para atender pedidos das áreas
  • Nenhuma área conhece bem os dados das outras — e o time central não conhece bem nenhuma
  • Dados entregues pelo time central ficam desatualizados porque ninguém da área os mantém
  • Cada área cria seus próprios "Data Lakes sombra" em planilhas e S3 não governados

O resultado

  • O time central se torna um bloqueio, não um habilitador
  • As áreas perdem a confiança nos dados centralizados
  • A empresa paga por uma plataforma de dados que ninguém usa de verdade
Data Mesh propõe inverter o modelo: em vez de um time central responsável por todos os dados, cada domínio de negócio é responsável pelos dados que gera — como se fossem produtos.
MACKENZIE

🕸️ Os 4 Princípios do Data Mesh

PrincípioO que significaExemplo prático
1. Domínios como donosCada área de negócio é responsável pelos dados que gera, mantém e disponibilizaO time de Vendas publica e mantém o dataset "pedidos confirmados" — com SLA, qualidade e documentação garantidos por eles
2. Dados como produtoCada domínio trata seu dado como produto: com qualidade garantida, SLA definido, documentação e canal de suporteO dataset "pedidos" tem uma página no catálogo, um owner de contato e um SLA de atualização de 1 hora
3. Infraestrutura como plataformaTI central fornece a plataforma (storage, pipeline, catálogo); os domínios a usam autonomamenteTI oferece templates de pipeline; cada domínio cria o seu sem depender de aprovação central
4. Governança federadaPadrões e políticas centrais (LGPD, qualidade mínima, classificação); execução descentralizada em cada domínioLGPD e classificação de sensibilidade são definidos centralmente pelo DPO; cada domínio aplica à sua realidade
MACKENZIE

🕸️ Quando Usar — e Quando Não Usar — Data Mesh

✅ Use quando

  • A organização tem muitas áreas produzindo dados independentemente
  • O time central de dados virou gargalo reconhecido
  • As áreas têm maturidade analítica para ser donas dos seus dados
  • A empresa já tem uma plataforma de dados consolidada (não é o primeiro passo)
  • Existe apoio executivo para mudar o modelo organizacional

⚠️ Evite quando

  • A empresa está começando sua jornada de dados
  • As áreas não têm capacidade técnica para gerir seus próprios dados
  • Não existe uma plataforma de dados madura para servir de base
  • A cultura organizacional é muito centralizada — a mudança seria traumática sem preparação
Data Mesh não é uma tecnologia — é um modelo organizacional. Implementar as ferramentas sem mudar a estrutura e a cultura é garantia de fracasso.
MACKENZIE

🕸️ Governança Centralizada vs. Data Mesh

DimensãoGovernança centralizadaData Mesh
Responsabilidade pelos dadosTime central de dadosCada domínio de negócio
Quem define a qualidadeTime central (com risco de regras sem contexto)Domínio (com contexto real) + padrões centrais mínimos
Velocidade de entregaLenta — tudo passa pelo gargalo centralRápida — domínio opera com autonomia
Risco de inconsistênciaBaixo — uma fonte da verdadeMaior — requer governança federada rigorosa
Escala organizacionalFunciona bem em empresas pequenas e médiasNecessário em empresas grandes e diversificadas
Pré-requisitoNenhum — ponto de partida naturalMaturidade técnica e organizacional elevada
Data Mesh e governança centralizada não são mutuamente exclusivos — muitas empresas operam com um modelo híbrido, com domínios maduros operando em mesh e domínios menores ainda sob governança central.

💬 Exercício Discursivo

Caso real: Processo da ANPD contra a Claro Brasil (2023)

MACKENZIE

🚨 ANPD × Claro Brasil — Incidente de Dados

Em 2023, a ANPD abriu processo administrativo sancionador contra a Claro Brasil S.A. após incidente de segurança que resultou no acesso não autorizado a dados pessoais de clientes: nome, CPF, endereço, dados de contrato e histórico de consumo de serviços de telecomunicações.

Deficiências identificadas pela investigação:

  • Menor privilégio Funcionários e prestadores tinham acesso a volumes muito superiores ao necessário para suas funções
  • Monitoramento Ausência de detecção de acessos atípicos a grandes volumes de dados
  • Transparência Processo de notificação dos titulares considerado insuficiente pela ANPD
  • Governança Controles organizacionais (treinamentos, políticas de acesso) inadequados para o volume de dados tratado
O caso foi um dos primeiros processos sancionadores de grande porte conduzidos pela ANPD — sinalizando a transição de uma fase de orientação para uma fase de aplicação efetiva da lei. (Fontes: Convergência Digital, Teletime, gov.br/anpd)
MACKENZIE

Grupos de 4–5 pessoas · 75 minutos

Questão 1 — Diagnóstico de governança e LGPD (20 min)

Quais princípios da LGPD foram violados no caso Claro? Qual papel de governança (CDO, Data Owner, Custodian, DPO) estava ausente ou disfuncional? Em qual nível do modelo de maturidade a empresa provavelmente estava? Justifique.

Questão 2 — Controles preventivos (25 min)

Proponha 3 controles concretos que teriam prevenido ou limitado o incidente. Para cada controle: o que faz, quem é responsável (papel de governança) e qual princípio da LGPD ou item do checklist ele endereça.

Questão 3 — Transferência para o seu setor (30 min)

Quais dados pessoais (ou sensíveis) são tratados no setor do grupo? Qual é a base legal para cada tratamento? Quais são os 3 maiores riscos de violação? O modelo centralizado ou Data Mesh faz mais sentido para o setor — e por quê?

📌 Síntese da Aula 6

Conceitos centrais

  • Governança é decisão de negócio — sem envolvimento do negócio, é burocracia técnica
  • Os 5 papéis têm fronteiras claras: Owner decide, Custodian implementa, DPO garante legalidade
  • Menor privilégio: cada pessoa acessa apenas o mínimo necessário para sua função
  • LGPD: toda coleta de dado pessoal precisa de base legal — sem exceções
  • Dado sensível exige controles mais rígidos e bases legais específicas
  • Data Mesh: solução para escala, não para começar — requer maturidade
